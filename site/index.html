THE METHOD

Every rank has a reason.

Rarity is calculated within a collection, using the frequency of its traits.

01

Count the traits

Measure how often each trait value appears. Missing traits matter too.

02

Measure the surprise

Less frequent values carry more information. Combine their contributions and normalize by the collection's entropy.

03

Make the order explicit

Unique trait counts take priority, followed by score. Token IDs give tied results a deterministic order.

GOOD QUESTIONS

Understand the result.

Does a rarity rank tell me an item's value?

No. Rarity describes how unusual traits are within the supplied collection. It does not predict price, demand, or artistic value.

Why can a lower score have a better rank?

The number of unique traits is the first sorting criterion. Score comes next. Compare both columns when interpreting a result.

Do I need to mint a collection first?

No. Supply a complete local set of tokens and their traits. The core scorer does not need a wallet, API key, or blockchain connection.

What changes in 1.0?

The work includes deterministic tie ordering, optional creator settings, a TypeScript implementation, and shared conformance fixtures. Unconfigured scoring preserves supported 0.7.5 behavior. See the changelog for changes under development.
